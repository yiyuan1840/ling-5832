## Step 2. Pre-tokenization, the thing before BPE

**Goal.** See what the three candidate splitters do, then compose two of them. This *is* TODO 1.

Add to your file:

```python
from tokenizers import pre_tokenizers

sample = hobbit[5700:5850]
print(repr(sample), "\n")

for name, p in [
    ("WhitespaceSplit", pre_tokenizers.WhitespaceSplit()),
    ("Punctuation",     pre_tokenizers.Punctuation()),
    ("Whitespace",      pre_tokenizers.Whitespace()),
]:
    print(f"{name:16s}", [tok for tok, _ in p.pre_tokenize_str(sample)][:12])
```

Expected:

```
WhitespaceSplit  ['ng', 'down', 'below', 'his', 'waist,', 'and', 'immense', 'black', 'boots.', '“Good', 'Morning!”', 'said']
Punctuation      ['ng \ndown below his waist', ',', ' and immense black \nboots', '.', ' \n\n', '“', 'Good Morning', '!', '”', ' said Bilbo', ',', ...]
Whitespace       ['ng', 'down', 'below', 'his', 'waist', ',', 'and', 'immense', 'black', 'boots', '.', '“']
```

Look hard at the first two, because neither is what we want and the reasons are opposite.
`WhitespaceSplit` leaves `waist,` and `Morning!”` glued together, so BPE would be free to learn
`Morning!”` as one vocabulary item. `Punctuation` splits the punctuation correctly but leaves
whole phrases like `' and immense black \nboots'` as single units, because it does not treat
space as a boundary at all.

Now compose them:

```python
combo = pre_tokenizers.Sequence([pre_tokenizers.WhitespaceSplit(),
                                 pre_tokenizers.Punctuation()])
print("combo", [tok for tok, _ in combo.pre_tokenize_str(sample)][:12])
```

You should get the same as `Whitespace` on this sample. That is expected and is not a reason to
prefer one over the other; they differ on runs of punctuation, which this sample does not have.
Try `'He said "no!" -- twice.'` and compare `Whitespace` against your combo. One of them keeps
`!"` together.

**Try the other order too**, `Sequence([Punctuation(), WhitespaceSplit()])`. It gives identical
output. Both are pure splitters that only ever subdivide, so composing them commutes. That is
worth knowing rather than guessing at.

**Question.** Our two books use different quote characters. If BPE were allowed to learn
`Morning!”` as a single vocabulary item, what would a model trained on that vocabulary actually
be detecting when it classifies a passage?

**Checkpoint.** The expression you just wrote is your answer to TODO 1.

## Step 3. Train a BPE vocabulary by hand

**Goal.** Call the library directly, so the scaffold holds no mysteries. This is TODO 2.

```python
from tokenizers import Tokenizer, models, trainers

tk = Tokenizer(models.BPE(unk_token="<unk>"))
tk.pre_tokenizer = combo
tk.train_from_iterator([hobbit, lostworld],
                       trainers.BpeTrainer(vocab_size=500, show_progress=False))

print("vocab size:", tk.get_vocab_size())
print("id of <unk>:", tk.token_to_id("<unk>"))
```

Expected:

```
vocab size: 500
id of <unk>: None
```

That `None` is the point of this step. You passed `unk_token="<unk>"` to the **model**, but the
token itself was never created, because only the **trainer** adds tokens to the vocabulary. Two
different objects, two different jobs. The model knows what to call an unknown; the trainer
decides what exists.

Fix it by telling the trainer:

```python
tk = Tokenizer(models.BPE(unk_token="<unk>"))
tk.pre_tokenizer = combo
tk.train_from_iterator([hobbit, lostworld], trainers.BpeTrainer(
    vocab_size=500, special_tokens=["<unk>", "<s>", "</s>"], show_progress=False))

print({s: tk.token_to_id(s) for s in ["<unk>", "<s>", "</s>"]})
```

Expected:

```
{'<unk>': 0, '<s>': 1, '</s>': 2}
```

Special tokens are added first, in the order given, so those indices are stable across every
vocabulary size. That is why the rest of the project can treat 0, 1 and 2 as constants.

**Question.** You asked for 500 and got 500. Now try 50000 and read the size back:

```
requested    500 -> realized    500
requested   4000 -> realized   4000
requested  50000 -> realized  17104
```

The corpus runs out of merges worth making, so the trainer quietly gives you fewer. Why must
code always read the realized size back rather than trusting what it requested? Think about
what happens in Part 2, where the vocabulary size goes into the denominator of the smoothing
formula.

## Step 4. The out of vocabulary experiment

**Goal.** Test the lecture's claim yourself. This is the conditional argument in TODO 2.

Lecture 3 says BPE has no out of vocabulary words, because the vocabulary starts from UTF-8.

```python
from tokenizers import decoders

probe = ["café", "你好", "☃", "naïve"]

for seeded in (False, True):
    t = Tokenizer(models.BPE(unk_token="<unk>"))
    t.pre_tokenizer = pre_tokenizers.ByteLevel(add_prefix_space=False)
    t.decoder = decoders.ByteLevel()
    kw = dict(vocab_size=2000, special_tokens=["<unk>", "<s>", "</s>"], show_progress=False)
    if seeded:
        kw["initial_alphabet"] = pre_tokenizers.ByteLevel.alphabet()
    t.train_from_iterator([hobbit, lostworld], trainers.BpeTrainer(**kw))

    n_unk = sum(t.encode(p).ids.count(0) for p in probe)
    exact = all(t.decode(t.encode(p).ids) == p for p in probe)
    print(f"seeded={str(seeded):5s}  unk tokens={n_unk:2d}  exact round trip={exact}")
```

Expected:

```
seeded=False  unk tokens=11  exact round trip=False
seeded=True   unk tokens= 0  exact round trip=True
```

The claim is true of the algorithm and false of the library default. The initial alphabet is
built from characters the *training corpus* contained, and two English novels contain no `é`.
Seeding all 256 byte characters is what actually delivers the property.

**Question.** Seeding makes unknown tokens impossible. Why is that not automatically better? A
hint: think about what happens to an unseen word under byte level encoding, and how many
never-before-seen contexts a trigram model then has to guess at in a row.

**Checkpoint.** You now know all four arguments TODO 2 needs, and why the fourth is conditional.

## Step 5. Encode and pad

**Goal.** Turn a sentence into indices and add sentence boundaries. This is TODO 3.

```python
t = Tokenizer(models.BPE(unk_token="<unk>"))
t.pre_tokenizer = combo
t.train_from_iterator([hobbit, lostworld], trainers.BpeTrainer(
    vocab_size=500, special_tokens=["<unk>", "<s>", "</s>"], show_progress=False))

e = t.encode("Bilbo went home.")
print(e.tokens)
print(e.ids)
```

Expected at 500, then try 4000:

```
V=500    ['Bilbo', 'went', 'ho', 'me', '.']
V=4000   ['Bilbo', 'went', 'home', '.']
```

There is the vocabulary size trade-off, concretely. A small vocabulary cannot afford an entry
for `home` and spends two tokens on it. Sequences get longer as the vocabulary gets smaller.

Now pad by hand:

```python
ids = t.encode("Bilbo went home.").ids
bigram  = [1] + ids + [2]
trigram = [1, 1] + ids + [2]
print("bigram ", bigram)
print("trigram", trigram)
print("events, bigram :", len(bigram) - 1)
print("events, trigram:", len(trigram) - 2)
```

The two event counts must be equal. An n-gram model of order `n` scores `len(seq) - (n-1)`
events, and with `n-1` opening symbols both come to `len(ids) + 1`.

**Three questions**, and I will ask you these:

1. Why have an opening symbol at all? What can the model express with it that it could not
   without?
2. Why exactly `n-1` of them?
3. The end symbol is predicted but never conditioned on. Why does the model stop being a
   probability distribution if you leave it out?
