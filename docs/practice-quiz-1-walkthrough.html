Question 1Chapter 2Answer: 17

Byte pair encoding vocabulary size

If you initialize byte pair encoding with a vocabulary of size 9 and then run the algorithm for 8 iterations, how large is the resulting vocabulary?

The idea

BPE learns its vocabulary by merging. It starts from a base vocabulary (usually the individual characters, plus an end of word marker), then repeats one operation: find the pair of adjacent symbols that occurs most often in the training text, and glue them into a single new symbol. That new symbol is added to the vocabulary. Nothing is ever removed, because the original symbols are still needed to tokenize words the merges do not cover.

Working it out

start 9 symbols each iteration +1 merged symbol after 8 9 + 8 = 17

So the answer is simply the starting size plus the number of merges. In the textbook's tiny example, the corpus of "low, lower, newest, widest" starts with 11 characters and each merge (e r → er, er _ → er_, n e → ne, and so on) adds exactly one entry.

Common mistake. Thinking a merge replaces two symbols with one and therefore shrinks the vocabulary by one. It does not. Both original symbols stay in the vocabulary; only the corpus representation gets shorter.
Question 2Chapter 2Answer: b

Heaps' Law

Which of the following statements follows from Heaps' Law when applied with the usual values for its constants?
  1. Growth in the size of a vocabulary approaches a fixed ceiling as a function of the size of the corpus.
  2. The size of a vocabulary grows without bound as a function of corpus size.

The idea

Heaps' Law relates the number of distinct word types |V| to the number of running tokens N in a corpus:

|V| = k · N^β with 0 < β < 1, typically about 0.4 to 0.6

The exponent β is positive, so as N grows, |V| keeps growing too. Because β is less than 1 the growth slows down (a square root curve is the mental picture), but slowing down is not the same as stopping. There is no limit that |V| converges to.

Why option a is tempting but wrong

If you plot |V| against N the curve visibly flattens, and it is natural to read that as "approaching a ceiling". But a ceiling would require β = 0. With any positive β, doubling the corpus always adds new types, just fewer of them each time. This matches everyday experience: no matter how much text you collect, you keep encountering new names, typos, technical terms, and coinages. It is also the reason unknown words are a permanent fact of life in language modeling, and why subword tokenization (Question 1) exists.

Common mistake. Confusing Heaps' Law (vocabulary size vs. corpus size) with Zipf's Law (word frequency vs. frequency rank). Both are power laws about vocabulary, and both appear in Chapter 2, but they answer different questions.
Question 3Chapter 3Answer: 1

Bigram conditional probability

<s> some are fast </s> <s> and some are slow </s> <s> some are high </s> <s> and some are low </s>
Using the corpus above, what is the conditional probability of seeing "some" having just seen the word "and", i.e. P(some | and)? Assume a bigram approach and no smoothing. Treat <s> and </s> as regular tokens.

The idea

A bigram model with no smoothing is just counting. The probability of a word given the previous word is the number of times the pair occurs, divided by the number of times the previous word occurs at all:

P(w₂ | w₁) = count(w₁ w₂) / count(w₁)

Working it out

  1. Count "and" in the corpus: it appears in lines 2 and 4, so count(and) = 2.
  2. Count the pair "and some": in both of those lines the next word is "some", so count(and some) = 2.
  3. Divide: 2 / 2 = 1.

Every time this corpus says "and", the next word is "some", so the model is certain. That is a normal outcome for an unsmoothed model trained on four sentences; the counts are tiny, so probabilities land on round numbers like 0, 0.25, 0.5, and 1.

Common mistake. Dividing by the total number of tokens (which would give a joint probability, P(and, some)) instead of dividing by count(and). The conditional probability asks "out of the times we saw 'and', how often was 'some' next?", so the denominator is count(and).
Question 4Chapter 3Answer: 0.125

Bigram sentence probability

Given the same corpus and a bigram model with no smoothing, what probability is assigned to the sentence <s> some are low </s>? Give a decimal, not a fraction.

The idea

The bigram model approximates the probability of a whole sentence as the product of one conditional probability per word, each conditioned only on the word before it. Including the start and end tokens, the sentence has four bigrams:

P(<s> some are low </s>) = P(some | <s>) · P(are | some) · P(low | are) · P(</s> | low)

Working it out

BigramPair countFirst word countProbability
P(some | <s>)240.5
P(are | some)441
P(low | are)140.25
P(</s> | low)111
0.5 × 1 × 0.25 × 1 = 0.125

Two of the four lines begin with "some", so the first factor is 0.5. "are" appears four times and is followed by "low" only once, giving 0.25. The other two bigrams are certain. Notice that the sentence being scored is literally line 4 of the corpus minus the word "and", yet its probability is well below 1, because the model only remembers pairs, not whole lines.

Common mistake. Forgetting the <s> and </s> tokens. Dropping P(some | <s>) would give 0.25 instead of 0.125. The question says to treat them as regular tokens, and in general the start token is what lets the model score the first real word at all.
Question 5Chapter 4Answer: [1.8, -0.6, -2.4, -0.6]

Softmax gradient for one class

Three way authorship classification with logistic regression: classes John, James, Alex. A training document from class James has feature vector [-3, 1, 4, 1]. The current model returns the softmax vector [0.2, 0.4, 0.4] over John, James, Alex. Give the gradient of the cross entropy loss for the James class.

The idea

For multinomial logistic regression, each class c has its own weight vector wc. The gradient of the cross entropy loss with respect to wc has a remarkably simple form:

∂L/∂w_c = (ŷ_c − y_c) · x ŷ_c the softmax probability the model gave class c y_c 1 if c is the true class, otherwise 0 x the input feature vector

In words: take the model's probability for that class, subtract what it should have been, and scale the input vector by that difference. This is the multi class version of the (ŷ − y)·x rule for binary logistic regression, and it is what gradient descent uses to update each class's weights.

Working it out

  1. James is the true class, so yJames = 1.
  2. The model gave James ŷJames = 0.4.
  3. The scalar is 0.4 − 1 = −0.6.
  4. Multiply every element of x by −0.6:
−0.6 × [−3, 1, 4, 1] = [1.8, −0.6, −2.4, −0.6]

The negative factor tells you the update will move the James weights in the same direction as x (since weights move against the gradient), which raises the score for the correct class. For the wrong classes the factor is positive: John's would be 0.2 − 0 = 0.2 and Alex's 0.4 − 0 = 0.4, pushing their weights away from x.

Common mistake. Getting the sign backwards by computing (y − ŷ)·x. That is the negative gradient, which is a valid update direction, but the question asks for the gradient itself. The first element being positive (1.8) is the tell.
Question 6Chapter 4Answer: −log 0.4

Cross entropy loss, label 1

Training example {x, 1} in binary logistic regression. The classifier assigns 0.4 to this input. What is the cross entropy loss for this single example?

The idea

Binary cross entropy loss for one example is

L(ŷ, y) = −[ y · log(ŷ) + (1 − y) · log(1 − ŷ) ]

Only one of the two terms survives, because y is either 0 or 1. The whole formula is a compact way of saying: take the negative log of the probability the model assigned to whichever answer was actually correct.

Working it out

Here y = 1, so the second term is multiplied by zero and disappears:

L = −log(ŷ) = −log(0.4) ≈ 0.92

Because 0.4 is less than 1, log(0.4) is negative, and the minus sign in front makes the loss positive. A model that had said 0.9 would have loss −log 0.9 ≈ 0.11, and one that said 1.0 would have loss 0. Lower confidence in the right answer means a bigger penalty.

Common mistake. Choosing −log 0.6 because it "looks like the leftover". The 0.6 is the probability the model gave to class 0, which is not the true class here.
Question 7Chapter 4Answer: −log 0.7

Cross entropy loss, label 0

Training example {x, 0}. The classifier assigns 0.3 to this input. What is the cross entropy loss for this single example?

Working it out

Same formula as Question 6, but now y = 0, so the first term vanishes and the second stays:

L = −(1 − 0) · log(1 − ŷ) = −log(1 − 0.3) = −log(0.7) ≈ 0.36

The classifier outputs the probability of class 1. Saying 0.3 for class 1 is the same as saying 0.7 for class 0, and class 0 is the correct label, so 0.7 is the probability of the right answer. The loss is fairly small, which makes sense: the model leaned the right way.

One rule for both questions

Questions 6 and 7 are mirror images. In both cases the loss is −log of the probability the model assigned to the true label. When the label is 1 that probability is ŷ; when the label is 0 it is 1 − ŷ. If you keep that sentence in your head you never need to expand the full formula.

Common mistake. Picking −log 0.3. That would be the loss if the label had been 1. Always ask first: what did the model say about the answer that was actually correct?
Question 8Chapter 4Answer: ln(3)

From probability back to logit

A binary classifier has assigned a probability of 0.75 to an item. Which of the following characterizes the logit that gave rise to this probability? Options: 3, ln(3), −ln(0.75), −ln(0.25).

The idea

In logistic regression the raw score z = w·x + b (the logit) is squashed into a probability by the sigmoid function. The logit function is the inverse of that, and it equals the natural log of the odds:

sigmoid: p = σ(z) = 1 / (1 + e^(−z)) logit: z = ln( p / (1 − p) )

Working it out

  1. Odds = p / (1 − p) = 0.75 / 0.25 = 3.
  2. Logit = ln(odds) = ln(3) ≈ 1.10.

Sanity check: σ(1.10) = 1 / (1 + e−1.10) = 1 / (1 + 0.333) = 0.75. A positive logit should give a probability above 0.5, and it does. A logit of 0 would give exactly 0.5, and a negative logit gives less than 0.5.

Common mistake. Answering 3, which is the odds rather than the log odds. The other two distractors, −ln(0.75) and −ln(0.25), are cross entropy loss expressions (see Questions 6 and 7), not logits. The quiz is deliberately mixing the two ideas to see whether you keep them apart.
